CastorPollux

CastorPollux is a desktop workspace for defensive binary analysis. It saves the evidence, review results, and logs for each investigation so you can inspect and revisit them.

Developer: Jason Bernier. Connect with Jason on LinkedIn.

How an investigation works

  1. Choose a binary and an output folder. CastorPollux records the target hash, format, architecture, and available symbols.
  2. Ghidra and REA analyze the binary. The app saves reconstructed pseudocode, functions, strings, imports, cross-references, coverage, and engine logs.
  3. Choose a review agent and inspect the evidence preview. The agent receives scoped text evidence and a defensive review prompt; it does not receive the binary through this workflow.
  4. Inspect findings, cited pseudocode, call paths, confidence reasons, and confirmation steps. Export a report in the formats you select.

What the results mean

Decompiler output is a reconstruction of program behavior, not the original source. A finding is a lead until a human confirms the relevant code path and build context. Coverage and engine errors remain visible so gaps are clear.

Other tools

CastorPollux supports saved investigations, build comparison, visual evidence graphs, REA actions and console commands, local plugins, symbol checks, and optional agent review. See Help for examples and Credits for component licenses.
