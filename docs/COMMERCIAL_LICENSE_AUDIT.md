# CastorPollux commercial distribution audit

This audit covers the bundled application and its third-party components. The distribution conclusions and outstanding obligations below apply to the first release.

Checked 2026-10-16 against the component files in this workspace. This is an engineering license inventory and issue list, not a legal opinion or clearance to ship. `CastorPollux-License-Inventory.json` lists 168 top-level installed REA npm packages, 7 nested npm packages (including development fixtures), and 26 pnpm embedded packages, their declared licenses and notice files, pnpm vendor executables, 103 Ghidra module license files plus shared license texts, 243 Temurin legal files, hashes of the bundled component archives, and the sidecar license documents. Optional user-installed agents and decompilers are outside the shipped EXE.

## Can the application be sold?

**In principle, yes. The current package is not yet cleared for paid redistribution.** REA's MIT, Ghidra's Apache 2.0 core, most bundled libraries, and PyInstaller's commercial bundling exception do not prohibit charging for CastorPollux. The complete Ghidra distribution also contains standalone GPLv3 support programs, Temurin is GPLv2 with the Classpath Exception, and the installed REA dependency tree includes an LGPL Frida binding with an exception. These permit commercial distribution under conditions; the terms do not become proprietary simply because they sit inside a self-extracting EXE. Source distribution or written offers, notices, and a final review of the exact binaries must be completed before selling this build.

## Release blockers and verification

1. Supply a compliant corresponding-source distribution or written offer for the included Temurin JDK and Ghidra GPL support programs, after legal review of the chosen GPLv2/GPLv3 route. If any Frida LGPL source obligation applies to the prebuild, address it too.
2. Review the exact `rea-agents` archive's notice gaps and any native prebuilds. REA's runtime notices are retained inside the EXE, but its own notice file expressly flags unresolved original copyright records for several packages. Remove or account for bundled test/example fixtures with unknown license metadata.
3. Resolve the pnpm `fastlist` vendor executable provenance and CustomTkinter's conflicting license metadata. Check Tcl/Tk notices and Python's bundled native libraries against the final EXE. This audit inventories the Python packages actually seen in the PyInstaller analysis manifest and the embedded runtime trees; it has not independently certified every byte in the large EXE.
4. Preserve the bundled archives' `licenses/`, `legal/`, and module `LICENSE.txt` files during extraction and updates. The GUI updater must rerun this audit when component versions change.
5. Set a product EULA that allows all recipient rights required by third-party licenses and does not imply endorsement by REA, NSA/Ghidra, or model vendors. Review trademark use and rights to target binaries and distributed pseudocode separately.
6. Have qualified counsel sign off on the final artifact and distribution method. A private internal build and a public paid download have different conveyance consequences.

The existing `CastorPollux-CREDITS.md`, `CastorPollux-Licenses/`, and upstream legal directories provide much of the required attribution. The release inventory reports this EXE as unsigned; code signing is a trust and distribution consideration, not an open-source license grant.
