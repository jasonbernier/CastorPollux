CastorPollux Help

Use the topic selector or search box above to find a task. Every scan is saved in its own investigation folder; History is the fastest way back to its evidence, logs, and reports.

Start here

  1. Open Analyze. Drop a binary on the target area or choose Browse.
  2. Choose an existing output folder. Optional PDB or DWARF symbols must match the exact binary build.
  3. Select Analyze → Agent Review for the full workflow, or Analyze for static evidence only.
  4. Watch stage percentage and activity output. Open History after completion to inspect saved work.

Example: scan C:\Samples\program.exe into C:\Investigations. The app creates a separate timestamped folder containing the copied target, manifest, pseudocode, evidence, and logs.

Analyze a binary

Ghidra imports the target and exports program evidence. REA runs analysis and procedure decompilation against the saved target. The Coverage page shows which procedures succeeded, failed, or remain pending. Missing symbols can reduce readable names without preventing a scan.

If an engine fails, open History → Logs and read the Ghidra and REA logs. Use Resume to retry incomplete stages in the same investigation. Do not assume a saved report covers procedures that failed decompilation.

Agent review

In Agent Review, select Codex, Claude Code, OpenCode, or a local Ollama model. Use Auto Detect or browse to an installed CLI. Choose review scope, report formats, and a minimum coverage threshold. Select Evidence Preview before cloud review to see the text that will be staged, including redactions.

The review prompt states the defensive purpose, requests evidence-backed findings, and asks for limits and confirmation steps. The agent reads staged pseudocode and analysis text from a local review folder. It does not decompile the target itself. Cloud agents may decline content; your static analysis remains saved.

Example: select Functions and enter 0x140001000, ParsePacket to focus review on those procedures. For a broad first pass, select All.

Browse evidence

Investigations searches functions, strings, imports, pseudocode, and cross-references. Coverage lists decompilation outcomes and confidence. Evidence Lab links pseudocode lines to binary addresses. Call Paths and Graph Lab show the path and supporting edges behind a finding.

Use Findings to open a cited procedure, inspect the code excerpt and call path, record a triage decision, and follow the confirmation checklist. A finding with low coverage or uncertain call edges needs extra manual review.

REA actions and console

REA Actions provides buttons for overview, strings, functions, decompilation, instructions, cross-references, and tracing. Select a saved investigation and enter a search term, function, or address. Overview works with an empty input.

REA Console accepts a JSON array of CLI arguments, without a shell. Example: ["--help"]. Use {binary} and {snapshot} placeholders for the saved target and REA snapshot. Review commands before running them because the full CLI includes operations beyond inspection.

History and recovery

History lists prior investigations with stage status, coverage, warnings, review state, and logs. Search by name or path. Open a record for its dashboard or results; use Resume for incomplete engine stages. Agent reviews are marked stale when analysis changes afterward.

Example: if Ghidra export fails but REA decompilation succeeds, History shows each status separately. Open Logs to see the exact engine error, then Resume the failed stage after correcting the engine installation.

Compare and report

Compare Builds highlights changed functions, strings, imports, and evidence. Findings tracking connects recurring or resolved issues across builds. Reports can include cited code, confidence reasons, call-path images, confirmation steps, and selected export formats, including SARIF.

To share a review, export a hash-verified investigation bundle or a diagnostic bundle with redaction. A report should be reviewed by a person before external disclosure.

Components and settings

Components shows installed Ghidra, Java, REA, and Node.js status. Run Health for a component check, Check Updates for available releases, and Roll Back to return to a prior working component. Settings → Engines lists required and optional tools and lets you adjust time and memory limits.

Optional symbol server lookup uses the allowlist and cache controls in Settings. A PDB identity mismatch means the symbols belong to a different build; choose the matching PDB or continue without it.

Plugins

Plugins are declarative JSON files. They can define source, sink, and sanitizer names, review guidance, and a report template. Select Create Sample on the Plugins screen, inspect the disabled example, and enable it only after adapting the rules to your organization.

Troubleshooting

  • Scan stopped: open History → Logs, check the engine stage and error, then use Resume after fixing the cause.
  • Agent review fails: verify the CLI path and login, inspect the staged evidence preview, and check the live output and review log.
  • Few findings: inspect Coverage and the minimum threshold. No findings does not prove the binary is safe.
  • Symbols rejected: match PDB GUID and age or ELF build ID with the exact build.
  • Window or text too small: use Settings → Appearance to adjust theme and text size.
