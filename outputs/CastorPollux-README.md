# CastorPollux

The Castor and Pollux Gemini mark identifies the desktop window and executable. The first run imports available settings and investigation history from the previous application-data folder.

**First release:** 1.0.0. CastorPollux bundles the desktop GUI, REA, Ghidra, Temurin JDK, and Node.js in a self-extracting Windows executable. Choose a binary and output folder to save reconstructed pseudocode, evidence, logs, and optional agent findings.

Use Credits search to inspect bundled licenses in the app. Settings offers font size, High Contrast, pane layout presets, optional tab reopening, and editable shortcuts with conflict checks. Keyboard focus has a visible ring, and unsaved Settings edits appear in the header. CastorPollux autosaves Analyze, Agent Review, Batch, and Settings form drafts locally; restored fields never start a scan or agent review. The additional literal redaction terms field is not saved. CastorPollux restores the last screen and selected files without starting a scan; after an interrupted session, a prompt shows stage status, redacted saved logs, and a verified resume choice for the earliest incomplete stage. Press Ctrl+K to search built-in commands by keyword, save actions, view recent actions, or clear command history. Press F1 for help about the current screen.

**CastorPollux.exe** is a self-extracting Windows desktop app for local binary analysis. It bundles REA, Ghidra, Temurin JDK, Node.js, and the GUI runtime. No separate Java or Node installation is required.

Project repository: [github.com/jasonbernier/CastorPollux](https://github.com/jasonbernier/CastorPollux). Executable downloads belong on its Releases page when a release is published.

## Use

1. Run `CastorPollux.exe`. The first launch may take longer while its embedded files extract.
2. On **Analyze**, choose a binary and an existing output folder. Click **Analyze → Agent Review** for the complete workflow, or **Analyze** to generate evidence only. Choose Codex, Claude Code, or OpenCode before starting the combined workflow.
3. The app makes a timestamped subfolder containing a verified copy of the input binary, Ghidra project, REA/Ghidra reconstructed source (`rea-pseudocode.c`), a procedure-level decompilation record (`rea-decompilation.json`), supplemental Ghidra pseudocode, disassembly, CSV exports including cross-references, REA evidence and snapshot JSON, logs, manifest, and HTML report. REA decompilation processes all listed local procedures in batches; progress appears in the status bar and activity log. Partial results and batch checkpoints are retained if a stage stops.
4. On **Components**, select **Check Updates**, then update individual engines or use **Update All**. Downloads come from the upstream projects and are verified against published checksums where available. REA and its dependencies are installed through bundled pnpm. A Ghidra release outside REA's supported Windows 12.1.x line is held for compatibility.
5. On **History**, see saved jobs and select **Resume** for an interrupted Ghidra, REA evidence, or REA decompilation stage. Jobs are recorded as soon as the saved binary has been verified, so they can be found after a crash or app restart. On **Investigations**, reopen a saved output folder and search functions, strings, imports, cross-references, call edges, REA code, and supplemental pseudocode.
6. **REA Actions** offers buttons for overview, string and function search, function dossiers, decompilation, instructions, cross-references, and traces. **REA Console** exposes the full REA CLI. Enter its arguments as a JSON array, use `{binary}` and `{snapshot}` placeholders, and run `["--help"]` to list commands. Console output is saved under `rea-console/`. REA includes operations beyond static inspection; review a command before running it.
7. On **Compare**, choose two saved investigations and an output folder. CastorPollux writes JSON, Markdown, and HTML differences for functions, strings, imports, and calls. Function matching is heuristic for anonymous functions.
8. On **Components**, use **Health** to test an engine or **Roll Back** to activate a retained previous version.
9. On **Agent Review**, select Codex, Claude Code, or OpenCode. The app locates common CLI installations automatically; **Auto Detect** checks again, and **Browse** supports a custom path. Select one or more JSON, Markdown, HTML, CSV, PDF, and SARIF report formats. Clicking **Run Review** sends a temporary copy of REA reconstructed source and supporting static exports to the selected agent; the binary and Ghidra project are excluded. Daybreak Blue is optional and off by default. For best security review results, use a Daybreak-enabled model by selecting it for Codex when your account has approved access; the option is also on Analyze for the one-click workflow. Without access, standard Codex and other agents still work. Each agent requires its own installed, authenticated CLI and may use a cloud service. Review requires successful REA decompilation; incomplete procedure coverage is recorded in the report. Model findings are hypotheses until validated.
10. **About** is a read-only HTML explanation of the pipeline, agent handoff, limitations, and sources, with a link to the project repository and future executable releases. **Help** contains a detailed topic-by-topic HTML user guide. Its editable local HTML copy can be opened from the page and lives under `%LOCALAPPDATA%\CastorPollux\Content`.
11. **Coverage** lists every REA procedure as successful, failed, or pending, with a heuristic decompiler-confidence label and reason. Search and filter it, inspect pseudocode or errors, and export the table as CSV.
12. **Findings** opens the current or archived structured review, lets you click evidence to see matching reconstructed code and cross-references, and saves analyst triage decisions and notes separately from the model output.
13. **Review Scope** can limit an agent to exact function names/addresses or Ghidra module/namespace names. **Prompt Preview** shows the request before review. Every successful review preserves its prompt and scope; subsequent reviews archive the preceding result.
14. **Offline Local Model** uses a separately installed Ollama server on `127.0.0.1:11434` and a downloaded local model. Check local models in Agent Review, then select `ollama`. CastorPollux's client does not contact a remote endpoint; for strict offline operation, disable Ollama cloud features in the Ollama server. Local reviews process code in bounded chunks and may take longer or produce weaker results than a cloud agent.
15. **Libraries & CVEs** shows versioned library fingerprint leads saved from a bounded local binary scan. **CHECK KNOWN CVEs** is opt-in and contacts NVD with product/version CPEs. Verify that code is embedded and relevant before treating an advisory as applicable. Agent Review can inspect the reconstructed code for potential new library-related vulnerabilities.

The Codex prompt template is included as `CastorPollux-Codex-Prompt.txt`. **Prompt Preview** shows the exact prompt with the chosen scope before a run, and successful reviews save it as `security-review-request.txt` in the investigation folder. Codex reads the staged source files; CastorPollux does not paste the entire pseudocode into the CLI prompt.

The reconstructed source is Ghidra pseudocode delivered through REA, not the original source code. The app stores updated components and job history under `%LOCALAPPDATA%\CastorPollux`. It connects to release sources only when you check for updates or install one. Binary analysis runs locally. Long-running analysis, REA queries, reviews, and searches use background threads to keep the GUI responsive; engine jobs are serialized to avoid conflicting Ghidra sessions. The component updater does not update CastorPollux itself.

## Data flow, team triage, and test corpus

**Data Flow** shows line-cited, intra-procedural source-to-sink leads from REA pseudocode and saves `data-flow.json`. These are heuristic candidates requiring manual validation. **Compare** tracks new, recurring, and absent agent findings when both investigations have structured reviews; absent findings are not proof of fixes. **Findings** records a reviewer, optional assignee, decision, and note and appends each action to the local `findings-audit.jsonl`. **Test Corpus** maintains expected findings by binary SHA-256 and evaluates saved investigations for missed findings and, on fully adjudicated cases, false positives. **Investigations** displays the saved target's Authenticode status and signer when available. These features are local; team sharing requires a shared folder with suitable access controls.

**Custom rules** live in `%LOCALAPPDATA%\CastorPollux\data-flow-rules.json`; Data Flow can create and open this editable file. Enabled declarative plugins under `%LOCALAPPDATA%\CastorPollux\Plugins` extend source, sink, and sanitizer rules, add agent review guidance, and generate extra Markdown reports. The package includes example JSON files.

On Analyze, choose an optional local PDB or DWARF sidecar. CastorPollux verifies a PDB GUID/age or ELF GNU build ID match before Ghidra receives it; the investigation stores a copy, hash, identity, and application status. Check Ghidra logs and function exports to confirm that names were imported. **Runtime Trace** (Windows Sandbox execution is UNTESTED in this build) prepares a Windows Sandbox job with networking and clipboard disabled, read-only binary input, bounded runtime, and sampled process/TCP metadata; Windows Sandbox must be installed separately. A correlated trace includes a clickable timeline with candidate pseudocode and cross-reference links; category matches do not prove execution. **Unpack** safely extracts ZIP, TAR, GZIP, and XZ archives and carves valid PE/ELF candidates from raw firmware, with documented coverage limits. **Bundles** exports all investigation files with individual SHA-256 hashes and verifies every file before import.

## Review quality and privacy

Findings shows why an agent confidence label needs scrutiny, provides bounded report-ready REA code excerpts, saves one static call-path PNG per finding, and offers a six-step analyst confirmation checklist. Report exports include these artifacts. Coverage can export `source-map.csv` and `source-map.json`, mapping reconstructed-code line ranges to binary addresses and available Ghidra symbols; these are not original source-file line numbers.


Agent Review defaults to an 80% procedure coverage threshold and requires at least 1,000 reconstructed source characters. Reports flag lower coverage. **EVIDENCE PREVIEW** shows the temporary text files sent to a cloud agent; **Redact cloud evidence** masks token-like strings and optional user-entered literal terms in those staged copies. RetDec can be installed separately for a local second decompiler comparison when a high or critical finding is reported. A matching function location is not proof of a vulnerability.

## Batch and release integrity

Use **Batch Jobs** in the GUI to queue multiple binaries, or run `CastorPollux.exe --batch CastorPollux-Batch-Example.json` after editing the sample paths. The app writes a JSON summary and log for CI; exit codes are 0 for complete, 2 for job or quality failure, and 3 for invalid configuration. See `CastorPollux-CI-Example.ps1`. On Components, export an inventory or inspect the EXE signature. The package includes hashes, a per-component license inventory, and a commercial distribution audit. The audit says this build is not yet cleared for paid redistribution until source and notice obligations are completed. Release signing requires the distributor's code-signing certificate and SignTool; this build is unsigned unless the inventory explicitly shows a valid signature. Component updates are checksum-verified against upstream sources, which is different from publisher signing.

See `CastorPollux-CREDITS.md`, `CastorPollux-Licenses/`, `CastorPollux-License-Inventory.json`, and `CastorPollux-Commercial-License-Audit.md` for sources, notices, and the commercial release status.
